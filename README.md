# エニグマ暗号文単独攻撃ツール

エニグマ M3（陸軍の3ローター式、リフレクター B）の暗号文を、平文の手がかり（クリブ）なしで
復号するツール。平文は英語と日本語ローマ字に対応する。プラグボードが分からない暗号文からも、
ローター・初期位置・リング・プラグボードの全設定を復元する。

解読機はコマンドライン版が3つ（プラグボード未知版・既知版・通常版）と、ブラウザで動く Web 版がある。
短文・クリブなし・プラグボードありの組み合わせが最も難しく、その対応を「解読の方法」に、
残っている制約を「精度と制約」にまとめた。

## 使い方

### Rust コアをビルドする（任意）

純Python部分は標準ライブラリだけで動く（Python 3.7 以上）。Rust コアはビルドしなくてもよく、
未ビルドなら自動で純Python版に切り替わる。結果は同じで、速度だけが違う。

```bash
# Python 3.14 では pyo3 0.22 が新しすぎると判断されるため、前方互換フラグが要る
cd enigma_decoder
PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1 maturin build --release
pip install target/wheels/enigma_decoder-*.whl
```

### プラグボードが分からない暗号文を解く（`decrypt_plugboard.py`）

```bash
python decrypt_plugboard.py             # 対話モード（暗号文と精度モードを尋ねる）
python decrypt_plugboard.py --selftest  # 動作確認（155字・6ペアを復元）
python decrypt_plugboard.py --lang english <暗号文>
python decrypt_plugboard.py --normal   <暗号文>   # 速いが粗い
python decrypt_plugboard.py --thorough <暗号文>   # 最大探索
```

精度モードは `MODE_PARAMS` で定義しており、Web の「精度」セレクタと同じものを使う。

| モード | 目安時間 | Phase C の候補数 | リング探索 | 使いどころ |
|---|---|---|---|---|
| `normal` 通常 | 5〜30 秒 | 60（短文 90）| 26通り | 150字以上・0〜3ペア |
| `accuracy` 精度（既定）| 20〜90 秒 | 200（短文 300）| 676通り | 迷ったらこれ |
| `thorough` 徹底 | 5〜30 分 | 600（短文 900）| 676通り | 100字未満＋4ペア以上 |

目安時間は Rust コアが有効な場合の値で、未ビルドだと大幅に延びる。短文（150字未満）では正解が
Phase A の上位から落ちやすいため、各モードの `width_scale` に比例して探索幅を自動で広げる。

### プラグボードが分かっている暗号文を解く（`decrypt_known_plugboard.py`）

```bash
python decrypt_known_plugboard.py             # 対話モード
python decrypt_known_plugboard.py --selftest  # 動作確認
python decrypt_known_plugboard.py --lang english <暗号文>
python decrypt_known_plugboard.py --accuracy <暗号文>   # リングを 676通り探索
```

プラグボードは `decrypt_known_plugboard.py` 冒頭の定数 `KNOWN_PLUGBOARD` に書いてあるので、
これを書き換えて指定する。Rust コアがあれば、50〜100字の短文は1件あたり約1秒で解読できる。

### 通常版で解く（`decrypt.py`）

VSCode で `decrypt.py` を開いて▷ボタンを押すか、ターミナルで実行する。

```bash
python decrypt.py             # 対話モード（暗号文・言語・モードを順に尋ねる）
python decrypt.py --selftest  # 既知平文で動作確認

python decrypt.py --lang english <暗号文>     # 言語を指定する
python decrypt.py --lang romaji  <暗号文>
python decrypt.py --accuracy <暗号文>         # モードを指定する
python decrypt.py --thorough <暗号文>
python decrypt.py ZWIYNSYAYCIALZVKMEVRKJW...  # 暗号文を引数で渡すと対話モードを飛ばす
python decrypt.py --lang romaji --accuracy ZWIYNSYAYCIAL...
```

対話モードでは、暗号文、平文の言語（1-3: auto / english / romaji）、探索モード（1-3: 通常 / 精度 / 徹底）の順に聞かれる。

探索モードは3つある。

- 通常（normal）: 約1〜3分。0〜2ペアのプラグボード向け。
  - Phase 1: ローター・位置を全探索（60×17576 通り）し、上位 200 候補を残す
  - Phase 2: 高速なプラグボード山登り（追加のみ、開始点1つ）
  - Refine: 右ローターのリング設定 26 通り
- 精度（accuracy）: 約10〜30分。短文と多めのプラグボード向け。
  - Phase 1: 上位 2000 候補（通常の10倍）、サンプル長 200字
  - Phase 2-1: 2000候補すべてに高速山登り（ふるい分け）
  - Phase 2-2: 上位 200 候補に完全山登り（既存ペアの解除・再配置を含む Gillogly 本来の山登り）と
    ランダム再開2回。局所最適に陥っても、複数の開始点で回避する
  - Refine: 中・右ローターのリング設定 26×26 通り
- 徹底（thorough）: 数時間以上（時間無制限）。4ペア以上や 30字台の短文向け。
  - Phase 1: 上位 20000 候補、サンプル長 300字
  - Phase 2-1/2: 精度モードと同じ方式で規模を大きくし、再開4回
  - PC の性能や暗号文の長さによっては丸一日かかるので、バックグラウンドで動かす

通常モードの期待精度:

| 文字数 | プラグボード | 期待精度 |
|---|---|---|
| 200+ | 0-2ペア | ほぼ100% |
| 100-200 | 0-2ペア | 90%以上 |
| 100-200 | 3ペア | 60-80%（要精度モード） |
| 100以下 | 3+ペア | 不安定（要精度/徹底モード） |

通常モードと精度モードの実測:

| ケース | 通常 | 精度 |
|---|---|---|
| 90字英文 + 3ペア | 8.9% | 100% |
| 192字英文 + 2ペア | 100% | 100% |

### ブラウザで解く（`web/`）

Next.js（App Router / TypeScript）で作った。解読を含めてすべてブラウザ内で完結するので、
静的ホスティング（Vercel 等）にそのまま載る。詳細は [`web/README.md`](web/README.md)。

- 生成機・復号機（`/machine`）: 内部状態を固定したエニグマで平文と暗号文を相互に変換する。
  エニグマを TypeScript に移植し（`AAAAA→BDZGO` で検証）、ブラウザ内で即時に実行する。
- 解読機（`/break/known-plugboard`, `/break/plugboard`）: Rust 解析コアを WebAssembly にし、
  CPU コア数ぶんの Web Worker で並列に実行する。暗号文はサーバーへ送らない。

```bash
cd web && npm install && npm run dev   # http://localhost:3000
```

### 結果の信頼度をスコア差で判断する

復号後、上位5候補がスコア順に表示される。第1候補と第2候補のスコア差で信頼度を判断する。

- 差 > 0.5 → 第1候補がほぼ確実に正解
- 差 > 0.2 → 第1候補が有力
- それ以下 → 複数候補を目視で確認する

スコア差が小さいときは、上位5候補を見比べて文意の通るものを選ぶ。

## 解読の方法

### プラグボード未知版は4つの段階で全設定を復元する

プラグボード未知版は、文献
[Ostwald & Weierud 2017, "Modern breaking of Enigma ciphertexts"](https://www.tandfonline.com/doi/abs/10.1080/01611194.2016.1238423)
の三段階スコアエスカレーションを実装している。

```
Phase A  ローター順＋初期位置 … IC + bigram-IC で全探索（プラグボード不変性を利用）
Phase C  プラグボード復元      … IC → bigram → trigram の三段階山登り
                                ＋マルチスタート＋SA 磨き上げ（Rust/Rayon 並列）
Phase B  リング設定            … 右→中ローターのリングを再探索
Phase D  最終検証              … n-gram＋単語リスト照合で候補確定
```

### プラグボードが合うまでは、IC と bigram で方向を決める（段階スコア）

プラグボードが数本しか合っていない段階では、復号文はまだランダムに近い。trigram/quadgram は
ノイズだらけで正しい方向を示せず、頑健な IC/bigram の方が信号が強い。プラグが増えて文が
復元されるにつれて高次の n-gram に切り替えると、識別力が最大になる。

同じ候補・同じ SA 予算で、trigram 単独の SA と比べた結果:

| 暗号文 | プラグボード | 段階スコア（本手法） | trigram 単独 SA |
|---|---|---|---|
| 125字 | 8ペア | 完全解読 | 完全解読 |
| 126字 | 10ペア | 完全解読 | 完全解読 |
| 126字 | 9ペア | 完全解読 | 失敗（別候補を誤選択）|

中程度の長さで多プラグという難しい条件で、段階スコアが優位だった。50〜65字の短文は情報理論的な
限界に近く、本手法でも余分なプラグを過学習することがある（どのアルゴリズムでも同じ壁）。

### 復号文の英語らしさを、大規模な n-gram 表で測る

解読の成否は、復号文が自然言語らしいかを測る言語モデルの質でほぼ決まる。そこで、大規模コーパス
（Pride and Prejudice / War and Peace / Shakespeare、計約390万字）から事前に計算した
n-gram 頻度表 `ngrams_en.txt.gz` を同梱した。

| | 旧（組み込み小コーパス）| 現（大規模 n-gram 表）|
|---|---|---|
| コーパス | 約3千字 | 約390万字 |
| trigram 網羅 | 8.3% | 48.9% |
| quadgram 網羅 | 0.5% | 15.3% |
| 単語リスト | 982語 | 8,806語 |

精度への効果（プラグボード未知・段階スコア・50〜150字×2〜10ペア 10ケース）:

| 言語モデル | 完全解読 | 文字一致率 |
|---|---|---|
| 小コーパス | 7/10 | 93.0% |
| 大規模 n-gram 表 | 10/10 | 100% |

`ngrams_en.txt.gz` が無い環境では、組み込みコーパスに自動で切り替わる（精度は落ちるが動作する）。

### 通常版は Gillogly 法の二段階攻撃で解く

通常版（`decrypt.py`）は Gillogly 法（1995）の二段階攻撃をもとにしている。

- Phase 1（ローター・初期位置の全探索）: ローター I-V から3つ選ぶ全 60 通り × 初期位置 26³ ≈
  100 万通りについて、プラグボードなしで先頭 N 文字を復号する。英語・ローマ字の trigram + quadgram
  対数確率（指定言語のみ、または両言語の最大値）で順位を付ける
- Phase 2（プラグボードの山登り）: 通常モードは各反復で「未使用の文字ペアを追加」だけを試す
  （高速だが局所最適に陥る）。精度・徹底モードは「ペアを設定（既存ペアの再配置を含む）」と
  「ペアを解除」の全操作を試し（Gillogly 本来の形）、空のプラグボードとランダムな初期
  プラグボード（3-5ペア）から複数回再開する
- Refine（リング設定）: ノッチを越えるタイミングがリング設定で変わるため、右ローター
  （精度モードでは中ローターも）のリングを再探索する

### プラグボードが分かれば、山登りを省いて速く解ける（既知版）

既知版は山登り（Phase 2）が要らないので、通常版より大幅に速く、精度も高い。

| | 通常版（`decrypt.py`） | 既知版（`decrypt_known_plugboard.py`） |
|---|---|---|
| Phase 1 | IC スコア（プラグボードなし）| n-gram スコア（既知 PB 適用、Rust 並列）|
| Phase 2 | 山登りで PB を推定（重い）| 不要 |
| 短文精度 | プラグボード数に依存 | 大幅向上（単語リスト照合を併用）|

Phase 1 の実装ごとの実測（50〜100字・非ゼロのリング設定・5ペア・最高精度モード）:

| Phase 1 実装 | 5ケース総時間 | 精度 |
|---|---|---|
| 純Python | 412秒 | 5/5 完全一致 |
| Rust + Rayon | 5.1秒（約80倍高速） | 5/5 完全一致 |

### アルゴリズムは Rust に1本化し、CLI とブラウザで共用する

アルゴリズム本体は `enigma_decoder/src/core.rs` に集約し、2つの入口を feature で切り替える。

| feature | 用途 | 並列化 | ビルド |
|---|---|---|---|
| `python`（既定）| ローカル CLI | Rayon | `maturin build --release` |
| `wasm` | ブラウザ | Web Worker（JS 側）| `cd web && npm run build:wasm` |

同じコードなので結果は一致する。言語モデルのスコアが Python と WASM で完全に一致することを、
`web/scripts/verify-wasm.mjs` で確認している。

## 精度と制約

### 短文は約34字が限界

プラグボードあり・暗号文単独で、大規模モデルを使うと約34字まで解読できることを確認した。
29〜33字はユニシティ距離を下回り、どの手法でも不安定になる。

### 暗号文の長さとプラグ数ごとの目安

短文・クリブなし・プラグボードありは、エニグマ攻撃の中で最も難しい。情報理論的な下限があり、
どのアルゴリズムでも次が壁になる。

暗号文の長さ:

- 200文字以上 → 安定して解読できる（通常モードで足りる）
- 100〜200文字 → 通常モードで多くの場合は解ける。3ペア以上なら精度モード
- 50〜100文字 → 精度モードを推奨。3ペア以上なら徹底モード
- 50文字未満 → 統計的な限界に近い。徹底モードでも複数候補から目視で選ぶ必要がある

プラグボードの接続数:

- 0〜2 ペア → ほぼ確実に解読できる
- 3 ペア → 短文では精度モードが必須
- 4〜5 ペア → 徹底モードで挑戦する。結果は文の長さ次第
- 6 ペア以上 → 短文では原理的に困難（軍用級の設定）

友人間などの暗号通信では通常 0〜3 ペアなので、精度モードまでで足りる。

### CLI は速度のために、捕捉した候補の一部を評価しない

プラグボード未知版の CLI と Web 版では、探索幅を意図的に変えている。CLI は Phase A の保持数
（`top_n`）より Phase C の実行数（`max_candidates`）を小さく取っており、速度と引き換えに
「捕捉できているのに評価されない候補」が出る。実測では 131字・3ペアで正解が Phase A の 537 位に
いたが、`max_candidates=200` で切られて失敗した（その候補だけを Phase C に通すと完全に復元できる）。
ブラウザ版は実行時間の上限が無いため、両者を1本化して全候補を評価する。
詳細は [`web/README.md`](web/README.md)。

### 対応していないことと、拡張の手がかり

- リフレクターは B のみ対応する（C は `enigma.py` に定義済みだが、攻撃ループは B 固定）
- 山登りは局所最適に陥ることがある。精度・徹底モードで複数の開始点を試し、部分的に緩和している
- `corpora.py` の `ENGLISH_CORPUS` / `ROMAJI_CORPUS` に、実際の友人の文体に近いテキストを足すと、
  n-gram 統計の精度が上がる
- M4（4ローター海軍式）に広げるには、`enigma.py` に第4ローター（β/γ）と薄型リフレクター
  （B-thin/C-thin）を追加する。探索空間が約 26 倍になるので、並列化を推奨する

## Phase C の最適化手法の比較（遺伝的アルゴリズムを含む）

Phase C の探索手法として遺伝的アルゴリズム（GA）も実装し、山登り法（HC）・焼きなまし法（SA）・
現行の組み合わせと、同じ適応度評価回数・同じ乱数シード・同じ層（Rust）で比べた。
GA は現行を下回った（正解の候補を与えたときの完全復元: 17/50 対 21/50、12/50 対 18/50）ので、
既定は現行のままにした。条件・全結果・考察は
[`docs/optimizer-comparison.md`](docs/optimizer-comparison.md)、再現用スクリプトは
[`tools/benchmark_optimizers.py`](tools/benchmark_optimizers.py) にある。

GA はオプトインで試せる（Rust コアの再ビルドが必要）:

```bash
python decrypt_plugboard.py --optimizer ga <暗号文>   # 既定は --optimizer staged（現行）
```
